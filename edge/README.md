# Optional edge layer: `Accept: text/markdown` negotiation

## Why this exists outside the site

[acceptmarkdown.com](https://acceptmarkdown.com) asks a compliant origin to do
four things:

1. serve markdown when the request carries `Accept: text/markdown`,
2. set `Vary: Accept` on those responses,
3. answer `406` when the client accepts neither variant,
4. honour q-values when ranking the two.

All four are **server** behaviours. mohammad.page is served by GitHub Pages,
which is a static file host: it never reads the request's `Accept` header and
gives no way to set a response header. Confirm it yourself:

```
$ curl -sI https://mohammad.page/ | grep -i '^vary'
vary: Accept-Encoding
```

That `Vary: Accept-Encoding` is Fastly's, not ours, and there is no
configuration file on GitHub Pages that can add to it. So the four rules cannot
be satisfied from this repository alone. What the repository *can* do — and now
does — is make sure the markdown actually exists at a stable URL:

- every page has a twin at the same path with a `.md` extension, generated by
  `scripts/build_markdown.py`,
- each HTML page advertises its twin with
  `<link rel="alternate" type="text/markdown">`,
- [`/llms.txt`](../llms.txt) and [`/agents.md`](../agents.md) tell agents to ask
  for the `.md` URL directly instead of relying on `Accept`.

## Turning on real negotiation

`markdown-negotiation.worker.js` is a Cloudflare Worker that closes the gap. It
sits in front of the existing GitHub Pages origin — no change to hosting, no
change to the repo — and implements exactly the four rules above using the
markdown twins this repo already builds.

Deploying it needs two things this repository does not have and should not
hold: **the domain's DNS on Cloudflare**, and **a Cloudflare account with
credentials**. Both are the owner's call, so the worker ships unwired.

### Steps

1. Move `mohammad.page` DNS to Cloudflare (free plan is enough) and keep the
   existing `CNAME` to GitHub Pages, proxied (orange cloud).
2. From `edge/`, deploy with [wrangler](https://developers.cloudflare.com/workers/wrangler/):

   ```
   npx wrangler deploy markdown-negotiation.worker.js \
     --name mohammad-page-markdown \
     --compatibility-date 2026-08-22
   ```

3. Add a route for the zone so the worker sees document requests:
   `mohammad.page/*`.
4. Verify:

   ```
   curl -sI -H 'Accept: text/markdown' https://mohammad.page/about
   # content-type: text/markdown; charset=utf-8
   # vary: Accept, Accept-Encoding

   curl -sI https://mohammad.page/about
   # content-type: text/html; charset=utf-8
   # vary: Accept, Accept-Encoding

   curl -s -o /dev/null -w '%{http_code}\n' \
     -H 'Accept: application/pdf' https://mohammad.page/about
   # 406

   curl -sI -H 'Accept: text/html;q=0.2, text/markdown;q=0.9' \
     https://mohammad.page/about
   # content-type: text/markdown; charset=utf-8
   ```

Cloudflare also offers a zero-config markdown toggle on some plans; it produces
converted markdown rather than the hand-checked twins in this repo, so prefer
the worker if you care about the output.

### Tests

`tests/markdown-negotiation.test.mjs` covers the negotiation logic — q-value
ranking, wildcards, the browser `*/*` case, the 406 case, and path-to-twin
mapping — without needing a deployment:

```
node --test
```
